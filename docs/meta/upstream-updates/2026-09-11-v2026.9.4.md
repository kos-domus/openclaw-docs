## What this release is

An update-resilience and plugin-workspace release. Theme: automatic rollback/recovery from compatible failed updates, a unified Plugins workspace (bundled + ClawHub), prepared cloud sessions with reusable snapshots, keyboard-driven question prompts in the TUI, GPT Image 2.5 variants, and externally managed configuration. No new Node floor or plugin-SDK breaking removals beyond what 2026.9.3 already shipped.

## Operator-relevant highlights

- **Update rollback/recovery**: eligible schema-neutral update failures now restore the retained previous package, command shim, service, and pre-activation configuration automatically; DB-migration-bearing upgrades still require a verified pre-update backup. (#140339)
- **Unified Plugins workspace**: discover bundled and ClawHub plugins, install from the Control UI, manage setup/settings/access in one place. (#135839 et al.)
- **Prepared cloud sessions**: start eligible Linux sessions from prepared local projects or public GitHub repos; build reusable snapshots from Settings → Connections → Cloud workers. Ready workers incur provider charges until deleted — disable via `cloudWorkers.profiles.<id>.readyWorkers: 0` or `cloudWorkers.preparedPool.maxTotal: 0`. (#143227 et al.)
- **TUI questions**: keyboard-driven choices, free-text answers, multi-question prompts in Gateway-connected and local TUI sessions; reopen pending prompts with `/question`. (#143273)
- **Read-only deployments**: `OPENCLAW_CONFIG_READONLY=1` keeps OpenClaw from rewriting deployment-managed config while preserving diagnostics and runtime state. (#140719)
- **Command review**: automatic command reviewer can allow/deny/escalate using bounded conversation context while retaining execution-policy authority. (#141987)
- **SDK deprecation entering**: `agent-harness-credential-prompt-string-argument` deprecated Sep 9, 2026; legacy string arg supported through Nov 30, 2026 — plugin authors should pass `{ controlToolsAvailable }`. (#143238)
- **SDK removal still pending**: `sdk-untrusted-context-identifier-aliases` passed its Sep 8 removal date but remains `removal-pending` while plugin readers migrate. (#142708)
